# Character engine contract v1

Pure ESM exports from `index.js`; no I/O, browser globals or external dependencies.

- `createCharacterSystem({ date = '-0300-01-01', polityId = 'hadara', polityName = 'Hadara', mode = 'realm', seed = 104729, familyId = 'family-arel', cities = [] })` returns state. Modes: `realm`, `family`.
- `normalizeCharacterSystem(raw)` returns a detached validated/migrated state, or `null` for absent state. Invalid or future versions throw a descriptive Error. Never advances time or draws randomness.
- `executeCharacterCommand(state, { id, expectedRevision, type, payload = {} })` returns `{ ok, state, events, error }`. Invalid command returns original state and an error string. Repeated accepted IDs return no extra effect. No arbitrary actor control: actor derives from campaign identity.
- `advanceCharacters(state, targetDate, { id } = {})` returns the same result shape. Calendar boundaries, not calls, trigger annual simulation. Same or past date never advances. An ended campaign stays at its actual end date, including when ending during a longer requested hop. Dates are Open Historia game dates, with no year zero.
- `getNextCharacterTransitionDate(state,targetDate)` returns the earliest pending annual, health-phase or household-exposure boundary, capped at the target. It returns `null` for ended campaigns or non-future targets. The adapter uses these boundaries for dated replay checkpoints.
- `getCharacterPresentation(state)` returns `{ date, revision, mode, identity, ruler, representative, families, people, offices, cities, religions, memories, stories, projects, actions, economy, succession, log, status, versions }`. Object collections here are arrays. Text is Swedish. Returns only public or player-known facts.
- `getCharacterWorldEffects(state)` returns `{ realmAlive, polityId, leaderId, leaderName, treasury, annualRevenue, productionMultiplier, militaryReadiness, legitimacy, cityEffects, orders, date, revision }`. Values are absolute projections; adapter must not add projections repeatedly or recreate a polity when `realmAlive` is false. `cityEffects`: `{id,name,regionId,familyId,governorId,productionMultiplier,taxIncome,unrest}`. `orders` is remaining public action capacity.
- `getAvailableCharacterActions(state)` returns the same actions as presentation.
- `getCharacterAge(person, date)`, `getPersonalOpinion(state, fromId, toId)` and `evaluateCharacterDecision(state, personId)` exported for validation/debugging.
- `canCharacterDirectRealm(state)` returns whether the current campaign representative can issue public state orders. Host legacy order paths must use this same query; family membership or an outside guardian alone never grants state command.

Action descriptor: `{ type, label, description, cost, stress, disabledReason, fields: [{ key, label, type: 'select', options: [{value,label}] }] }`. Payload keys are declared in each action's fields. Actions may be rendered generically. Selection-specific checks occur again when submitted. `cost` and `stress` are display strings; `disabledReason` is empty when broadly available. All selectable entities have stable IDs.

Presentation story: `{id,type,title,description,actorId,targetId,createdAt,dueAt,status,choices:[{id,label,description,cost,stress,disabledReason}]}`. Resolve via command type `resolve_story`, payload `{storyId, choiceId}`. Choices should be displayed even if disabled, with reason. Engine always supplies a viable fallback for open stories.

State has `schemaVersion:1`, `rulesVersion`, `contentVersion`, `revision`, `date`, `nextAnnualDate`, `rngState`, `identity:{mode,polityId,familyId}`, `realm`, `people`, `families`, `offices`, `cities`, `religions` (ID-keyed objects), `relations`, `memories`, `stories`, `projects`, `log`, `appliedCommandIds`, `status`. The adapter persists the whole state verbatim and uses the presentation API rather than relying on internal derived fields.

Events returned by mutation: `{id,date,type,title,description,participants,public:true}`. Pure chronological outcomes. The runtime adapter owns their conversion to Open Historia impacts and replay; `events` never mutate the host world themselves.

Progression can be invoked locally without an LLM. Realm/family commands, budgets, stresses, stories and succession share one state. Long hops use stable annual boundaries and saved randomness. State remains serializable to JSON. Original content and balance constants are our own design, not claimed copies of proprietary code.

## Recurring character decisions

`storyDirector.js` owns the recurring catalogue and selection stream. Its saved `storyDirector` record has its own version, RNG, sequence, cooldown dates and last scheduling boundary. Absent records receive deterministic defaults for older pre-release saves. Normalization draws no randomness and creates no historical stories. Unknown versions or invalid director data are rejected. Only the version is exposed through presentation.

The director selects from real participants and current circumstances. Eight templates cover household tension, a promising student, a temple petition, a governor audit, a veteran petition, reconciliation, exile contacts and a returned favor. Personality changes candidate weights and action stress. A remembered dispute supplies the cause for reconciliation; a support memory can lead to a favor after three years. An actual family head can carry that favor after the original beneficiary dies. Once resolved, a source memory cannot be claimed again.

Selection occurs at annual boundaries, at most once per year, with a 36-month template cooldown, a 24-month participant cooldown and at most two open recurring stories. The independent RNG does not consume the life or health streams. Choices still affect later simulation through their documented changes to people and resources.

These stories use `type: 'character_event'` and an `eventType` from the catalogue. They retain participant IDs, the player representative and family at creation, `triggerDescription`, a twelve-month deadline, and a causal memory ID when applicable. The generic `resolve_story` command validates the current cast, funds and authority before applying a choice. Success adds a linked outcome memory and opinion cause. A payment offered in return for support transfers existing personal wealth to the family treasury.

Expired stories use the displayed free fallback. Death or a relevant change of representative, office or mandate closes a stale story without spending money. State and family campaigns retain separate authority and wallets. An exile offer records its accepted host and closes if that host changes or is lost. It does not grant control over the host.

The host adapter's `pauseForCharacterDecisions` option stops a longer advance at a newly opened recurring story. The playable turn horizon and model forecast enable this option alongside `pauseForHealthDecisions`; health has priority if both appear at the same boundary. Forecast and committed replay use the same dated transitions. Direct engine callers can still simulate longer periods and let unanswered decisions expire.

## Implemented presentation details

People include `age, alive, familyName, archetypeLabel, traitLabels, roleNames, opinion, opinionReasons, relations, stressLevel, goalLabel`. `opinionReasons` are `{label,value,causeId?,expiresAt?}` for opinion toward the current representative. `relations` are `{targetId,targetName,types}`. Other actors' private decision traces are not exposed. Families include `headName, guardianName, support, supportReasons, income, memberIds, officeCount, statusLabel`; support reasons are `{label,value}` and the final sum is clamped to 0–100.

Portraits: `person.portraitState` now supplies the identity-preserving state and age lookup described below. Older `portraitId` and `portraitAgeGroup` fields remain available for legacy assets, including six generic age/sex fallback keys. Consumers of the new atlas must use `portraitState` and their actual asset manifest. Core does not load image files or assume every proposed variant exists.

Family officials can submit `exercise_office` with `{officeId,policy:'service'|'patronage'}`. The active representative must hold the office personally. This consumes the office's own budget and one action, with a yearly cooldown. Service changes actual city infrastructure/unrest, army strength, legitimacy or religious support. Patronage transfers bounded funds and influence to the family with stress and political consequences. Relatives' offices cannot be controlled through this action.

Existing campaign saves without a character system are initialized by the host adapter. This is the first character schema; unknown character schema/rules/content versions are rejected without mutating input, not guessed into a new campaign.

Independent adult relatives may form their own marriages during calendar simulation. Only the active player representative is excluded from autonomous marriage. This follows the same personal autonomy rule as other families and avoids making manual matchmaking mandatory for every descendant.

## Lawful succession and regency

Royal executive authority is independent of campaign mode. A living minor needs a matching active royal regent who is an adult. An unresolved contested handover or missing executive prevents royal decisions. Family mode grants state control only when the family's head holds the crown or regency and its active representative is the royal executive; a separate family guardianship never grants state control.

Royal vetoes also apply when the controlled family's head is the royal regent. Family and royal mandates retain separate action scopes. Annual NPC appointments stop when the player controls the royal executive. Otherwise each appointment uses the executive's opinion, checks the royal veto, and consumes one matching royal consent on success.

NPC office-promise choices (`observe`, `support`, `advocate`) use the adult executive's personality and royal authority. A blocked choice spends nothing. `defer` preserves the story in `waiting` for one year without payment; automatic expiry selects that option when available. A promise itself does not consume appointment consent; its later fulfillment must pass the current checks. See [Regency authority](../../../docs/design/regency-authority.md) for the decision and payment rules.

Waiting `office_promise`, `promise_due` and `legacy_claim` stories enter the transition calendar at `dueAt`. The common story refresh reopens them on that date and records `reopenedAt`. Automatic expiry uses that timestamp, falling back to `createdAt` for older stories, so reopening never causes same-update expiry. Reads and duplicate advances do not reopen or log the story twice.

When present, `reopenedAt` must be a canonical date string between `createdAt` and the saved date. Its related creation and due dates must also be canonical. An open or resolved story cannot reopen before its deadline. A waiting story with a previous reopening must have a later deadline for its next review. A closed story may have been withdrawn before that next deadline. New follow-up promises omit the parent's reopening timestamp. Older stories without this field remain compatible.

The first, unreleased schema gains deterministic additive defaults for `regencies`, `externalHosts`, `realm.lawfulRulerId`, `realm.legalHeirId`, `realm.claimHistory` and `family.claims`. Version numbers remain unchanged. Normalization supplies absent defaults without drawing RNG or advancing time, then validates references. Older pre-release states without a legal history establish their current ruler as the initial lawful ruler; missing historical claims are not invented.

Actual control remains `offices.ruler.holderId`. A seizure preserves the lawful ruler. That person's death transmits the lawful claim under the succession rule independently of actual office control. Claim records preserve their origin, date and active/superseded/deceased/transferred/suspended status. The overlooked claimant's family receives a visible −12 support cause. `press_claim` restores its actual lawful claimant, even when the family's representative is someone else: it requires 45 influence and receives +20 power support; an ordinary political challenge requires 60. A current ruler may use `recognize_claim` to restore the lawful claimant, paying an action and surrender stress. Neither action recreates a dissolved realm.

Presentation `governance` and the additive fields in `succession` contain `actualRulerId/Name`, `lawfulRulerId/Name`, `legalHeirId/Name`, `contestedCrown`, `claimHistory`, enriched `claims`, relevant `regencies`, `realmAlive` and `externalHosts`. Regent records include `id`, `principalId/Name`, `regentId/Name`, `phase`, `grants`, `requestAfter` and `vetoedActions`.

`SUCCESSION_LAWS` is `['primogeniture', 'merit', 'elective']`, with Swedish labels `förstfödslorätt`, `förtjänst` and `val` in `SUCCESSION_LAW_LABELS_SV`. The legislator's `succession_law` reform cycles the three in that order, and an unknown law restarts at `primogeniture`. Under `elective`, `electiveCandidates` (`server/characters/election.js`) ranks the living adults of the old ruler's family by merit, then that family's minors eldest first, then the living adults of every other family by merit. The old ruler's spouse and every other legal parent of the old ruler's legal children stand with the other families. Minors outside the ruling family never qualify; a minor of the ruling family rules under a regency. When the list is empty on a ruler's death, `electOutsider` writes one generated person and one family and crowns that person with the event reason `Valet föll på en person utanför hovet`. The person is named `Vald härskare <n> (genererad)` in `Valt hus <n> (genererat)`, where `<n>` counts the elections from outside in this campaign. The electee is 40 years old, `steward`, `dutiful`, has every skill at 5 and takes the dead ruler's religion and culture. Ids come from `state.sequence`, and the election draws no randomness. A historical campaign marks the person `identityOrigin: 'generated'` with generated claims. Under `primogeniture` and `merit` an empty list still ends the realm, and abdication with no candidate still refuses.

Regency phases are `minority`, `contested`, `ended`, `closed`. Office and family mandates remain separate. Family guardians reserve estate investment and adoption; royal regents reserve appointments, dismissals, banishment, taxation and archetype actions. Personality determines the veto. Ordinary private livelihood and support-building remain available. Story appointments obey the same veto as direct appointments. Majority normally ends the mandate; an ambitious regent with loyalty below 70 and family influence at least 40 can contest it. During a disputed royal handover, `canCharacterDirectRealm` is false. The prototype does not yet model a separate adult-incapacity state.

- `request_regent_consent {regencyId,actionType,approach}`: `negotiate` costs 10 family silver, `compensate` costs 30 and transfers it to the regent, `appeal` costs 15 influence. Cooperation is regent loyalty + opinion toward the principal /2 −15 for ambition; negotiation needs 60, compensation adds 35. A council appeal needs family influence + principal diplomacy ×3 at least 65. Refusal still consumes the stated cost and improves the regent's opinion; the same decision can be raised again after a year. Successful consent lasts one year and permits exactly one successful matching command.
- `resolve_regency {regencyId,approach}`: only a contested adult handover. `pension` costs 40 family silver and guarantees a negotiated transfer; `council` costs 20 influence; `confront` costs 25 silver and risky stress. Council/confrontation compare family influence + principal diplomacy ×3 (plus command ×3 for confrontation) against regent-family influence ×0.6 + disloyalty ×0.5 +15 for ambition; confrontation needs 8 more support. Failure costs resources, influence and stress. Success closes that specific mandate and its personal effects.

## Actual realm dissolution and external refuge

These are host-only transitions, using the same `{ok,state,events,error}` result, idempotent IDs and atomic failure behavior as commands. `id` must match `[a-zA-Z0-9_:.-]{1,160}`. The supplied `date` must equal the already advanced state date.

- `applyRealmDissolution(state,{id,date,reason,hostCandidates,hostPolityId?,hostAccepted?})`: call only after the world host has actually accepted the polity's dissolution. It sets `realm.alive=false`, closes public offices/budgets/projects and public claim stories, suspends claims, preserves private assets, and retains the original `identity.polityId` as the campaign anchor. Realm mode ends. A surviving family continues exiled and initially unhoused. An initially accepted host requires `hostAccepted:true` and an actual matching candidate; no recipient or new state is invented.
- `reconcileExternalHosts(state,{id,date,hostCandidates,hostAliases?})`: call after actual host-world actor changes. Unchanged context returns the original state without revision/event changes. A missing accepted recipient removes protection and records its loss. Validated aliases `{oldId:newId}` preserve accepted protection only when the alias target exists in the supplied candidate list. Aliases must come from a validated world rename, never a guessed successor state.

Host candidates are actual existing external polities supplied by the runtime: `{id,name,opinion:0,refugeThreshold:55,admissionCost:20}`. Core stores at most 24, giving already accepted hosts priority before truncation. Send the complete candidate list, or preserve these hosts before any adapter-side truncation. The runtime revalidates the chosen recipient against the current world at command time.

`seek_refuge {polityId}` is available to an exiled family after realm dissolution. It costs the candidate's admission price and one action. Acceptance requires family influence + actor diplomacy ×3 + recipient opinion /2 to meet `refugeThreshold`. Acceptance records `family.hostPolityId`, `hostPolityName`, `refugeAcceptedAt`; refusal records the event, retains the unhoused situation, and permits another attempt after one year. Accepted protection enables private estate investment and limited estate access; it grants no public command. Loss of the recipient removes those rights. Private livelihood, family relations and education remain available without state funds. Local `seek_patron`, return to the extinct realm, former public offices and restoration by a bare `press_claim` are refused. The prototype represents political residence, not a geographic travel route or ownership of foreign offices.

Validation: `node --test src/runtime/characters/characters.test.js src/runtime/characters/governance.test.js src/runtime/characters/health.test.js`. The governance file covers separate lawful/actual succession, three distinct political/private recipients, consent/veto, contested adulthood, dissolution, external acceptance/refusal, alias preservation, lost protection, bounded host lists and malformed saved references.

## Read-only succession forecast

`getSuccessionForecast(state)` returns the same serializable value exposed as
`presentation.succession.forecast`. It contains actual and lawful identities,
the expected actual successor, current exercised and incoming abilities,
authority limits, campaign identity implications and project continuity by
owner. No forecast fields are persisted.

The forecast is conditional on only the current ruler dying at today's date.
It shares the death-successor branch and candidate ranking with the runtime.
Optional candidate exclusions remove the departing person's office seats,
personal sanctuary support and claim penalty from merit scores. Viewing does
not simulate a transition, change state or consume RNG. Minor successors
require regency; their own ability is not immediately exercisable. A deceased
legal fallback is rejected by the shared selector so an exhausted population
reaches the existing interregnum path.

A minor without a living adult representative retains the nominal ruler
identity but has no current exercised ability in the forecast.

Under the elective law an empty candidate list sets `electionFromOutside: true`
and the authority line `Ingen vuxen vid hovet är behörig. Valet faller på en
genererad person utanför hovet.` The forecast creates nobody, and
`refreshLegalClaims` leaves `legalHeirId` null in that case. The heir claim
origin names the law in Swedish, for example `enligt val`.

See `docs/design/succession-forecast.md` and
`src/runtime/characters/successionForecast.test.js` for scope and checks.

## Temporary adult incapacity

Severe active or recovering smallpox, fever and injury temporarily prevent an adult from exercising a mandate. `mandateVersion:1` adds stable episode and representative-term identifiers. Royal and household authority, actors and treasuries remain separate. Replacement invalidates the previous representative's consent; recovery changes neither nominal ownership nor lawful succession. Minority handover waits until a sick adult principal recovers. A contested handover retains its named claimant and supplies no executive authority. Personal bonuses pause without moving their owner or end date. See `docs/design/character-capacity.md` for the lifecycle, candidate rules and migration contract.

## Health, care and dated portraits

The additive health module has `healthVersion:1`, `healthActivatedAt`, `healthRngState` and `healthSequence`. Its random stream and identifiers are separate from the existing annual stream. Normalization of older pre-release saves adds a neutral empty health history and stable portrait identities at the saved date. It does not invent historical illnesses, age people or draw random numbers. Unknown health versions and malformed condition references are refused. Existing schema/rules/content version numbers remain unchanged for this unreleased additive extension.

Each person has `healthConditions:[]`, `portraitIdentityId` and a locked `portraitFallbackIdentityId`. A saved condition contains `id,kind,stage,severity,startedAt,nextTransitionAt,nextExposureAt,stageHistory,treatment,causeId,sourceKind,relatedPersonId,scarRoll,outcomeRoll,endedAt` and, after a fatal outcome, `fatalAt`. Kinds are `smallpox`, `fever`, `injury`, `bereavement`; stages are `active`, `recovering`, `scarred`, `resolved`. Histories and causal memories persist after recovery. Public presentation omits the saved random outcomes and future phase/exposure deadlines, and adds `label,stageLabel,active`. Deceased people's remaining active phases are described as having been in progress at death.

Ordinary illness and injury arise during annual simulation, based on saved randomness, health/stress, previous disease and actual military office. Smallpox can expose actual members of the same household one month after onset, at most twice per source. Previous smallpox grants immunity in this game model. The exact active/recovery boundaries are processed even inside a longer hop: untreated smallpox uses three plus six months, injury four plus three, fever one plus two. Real death of a spouse, legal parent or child causes a two-year grief phase with a retained causal memory. These are gameplay times and probabilities, not clinical advice or a reconstruction of historical incidence.

Physical conditions reduce health, increase stress and lower the affected governor's production or general's military readiness. Their burden decreases during recovery and ends when healed, including when scars remain. A fatal course enters the normal death, property, family and lawful succession transition. All illness deaths at the same boundary are marked before any successor is selected. Existing annual mortality also continues to apply.

- `provide_care {personId,conditionId,care:'rest'|'physician'}` requires a living, untreated patient in the controlled household, a valid adult representative and sufficient family resources. Rest costs 5 family silver, a physician 20; the direct command also uses one action. Treatment is recorded once, changes risk and may shorten a phase, but never rerolls the saved outcome or cures instantly.
- Open `health_care` stories expose `physician`, `rest`, `watch` through the standard `resolve_story` command. Story choices use the same family costs and no action point; watch is a valid free choice. Closing or resolving a story does not invent a cure. Independent adult NPCs can use their own personal purse; they cannot spend player-family money or a minor's inherited assets autonomously.
- There is no player command, model operation or free-text override for inducing a condition or assigning a health value. Model suggestions about health remain advisory (see Model proposals and the gate). The annual engine and existing actual death transitions are the sources of these conditions.

`advanceCharacters` remains a deterministic full-target simulation. The adapter should stop an interactive hop when a newly opened actionable `health_care` story appears before the user's outer target, present that actual date and retain the unexpired illness. Its inner boundary calls alone cannot detect that a larger user hop needs to stop. A first one-year annual outbreak ends at the onset date, with an acute portrait and a valid choice; no artificial multi-year illness is needed to provide a decision window. Silent exposure checks still advance saved health RNG but should be merged into the next public checkpoint rather than producing filler cards.

`resolvePortraitState(person,date,{family}={})` is pure and also exported through `index.js`. It returns `{identityId,fallbackIdentityId,usesSharedFallback,ageGroup,visualState,stateKeys,expression,context,lifeStatus,variantKey,variantCandidates,reasons}`. Reasons are `{key,label,conditionId?,since?}`. `variantKey` is `${identityId}__${ageGroup}__${visualState}`. All candidates keep the same age group, trying the person's identity and then its locked shared identity. Asset existence is the consumer's responsibility; missing assets must not create broken requests or a different person's identity.

The atlas contract has exactly 12 states in this order: `healthy,smallpox,smallpox-recovering,smallpox-scars,fever,wounded,injury-recovering,injury-scars,frail,stressed,grieving,exiled`. Three age groups are `child` below 18, `adult` 18–59 and `elder` 60+. A six-column atlas uses rows 0–1, 2–3 and 4–5 respectively. Priority for the primary image is acute smallpox, wound, fever, smallpox recovery, injury recovery, smallpox scars, injury scars, frailty, stress, grief, exile, healthy. Every concurrent cause remains in `stateKeys` and `reasons`, with independent expression/context metadata; this is not a promise of images for every Cartesian combination.

All 24 initial identities retain their own atlas as they age. A newly born person's own stable ID remains its logical identity; its shared illustration is locked at birth to the same family's same-sex child seed (`person-f-4` female or `person-f-5` male). An unrecognized family may inherit an appropriate same-sex parent's younger seed illustration, otherwise it receives a deterministic matching child-seed fallback. Adoption or crossing an age boundary does not switch that identity. `usesSharedFallback:true` must be represented honestly: these are shared family illustrations, not newly generated unique faces. The three image ages are coarse stages, not exact-year portraits.

`deathAppearance` freezes the last actual age, primary state and concurrent reasons before a person is marked deceased. Later time, stress or family exile cannot change that memorial portrait. Imprisonment is a domain record (see Prisoners below), never inferred from fear or exile, and no prison portrait is invented.

## Contested actions and schemes

`attempt_action` (payload `{ actionId, actorId, targetIds, means: { silver, agentRoles, secretId?, hookId?, topic? } }`; `secretId` is blackmail's secret, `hookId` an optional poison hook, `topic` a spread_rumor topic, and any other key is refused) runs a contested catalog entry (`actionCatalog.js`). `estimateAction` validates it and gives integer odds from 5 to 95; the attempt is paid once through `payForAction`, an ordered actor other than the active representative draws a refusal first, and two rolls on `state.actionRngState` (success, then secrecy) pick one of five tiers whose effect envelope applies at its defaults. `record_action_narrative` may later move a ranged effect inside its envelope; `handleCommand` accepts it only with `command.origin === 'narrate'`, which `recordCharacterNarrative` in `characterRuntime.js` is the only caller to set, and refuses any other origin with 'Berättelsen kan bara skrivas av berättarsteget.'. An entry with `durationMonths > 0` starts a scheme instead (`schemes.js`): paid and ordered at the start, checked for discovery monthly, rolled on its due date. An active scheme that collapses reaches the player only as the plan of the player or the controlled family; its target never hears of a plan nobody saw through. `abort_scheme` and `reinforce_scheme` act on the controlled family's own active schemes. A hook an active scheme holds in `means.hookId` starts no other attempt and leaves the menu (`Övertaget är bundet till en pågående plan.`, shared with conversations through `secrets.js`); the scheme itself still uses it on its due date. A secret that already gave its actor a hook, shown by a `hook_from_secret` effect of that actor in `actionLog`, is no longer usable by that actor or offered to them; a spent hook does not change this, and other holders are not affected. The catalog in presentation evaluates entries for the active representative as acting person; the controlled family pays. `state.rngState` is never touched by these commands.

## Prisoners

`state.prisoners` holds `{ id: 'prisoner-<n>', personId, captorFamilyId, since, ransom: 40, status, closedAt, reason }`. `status` is `held` while the person sits in prison (`closedAt` and `reason` are null) and `released`, `ransomed`, `executed` or `dead` once the record is closed (a date and a Swedish reason); a record closes once. `isImprisoned(state, personId)` is the one question the rest of the engine asks. An imprisoned person cannot act (`Personen sitter fängslad.` from `estimateAction`), holds no office (`imprisonPerson` vacates the non-ruler offices through `assignOffice`, `appoint` refuses a prisoner), takes no yearly decision in `aiAnnual`, is no feast guest, brings no directed story, fills no role of a new event chain, and a scheme the person runs as actor collapses at its next check. A prisoner never acts for a family or the realm: `householdRepresentative` is null while the principal or the guardian sits in prison, `realmExecutive` is null while the principal or the regent does, the mandate episodes pass `excluded` to `selectMandateRegent` so no prisoner is chosen regent or guardian, and a new family head is the eldest living member outside prison (the eldest prisoner only when every member sits in prison). `imprisonPerson` refuses the ruler (`Härskaren kan inte fängslas.`) and the active or household representative (`Den som företräder familjen eller riket kan inte fängslas.`) through `imprisonRefusal`; the `imprison` action effect then reports `applied: false`. Death closes the record as `dead`; a prisoner who becomes ruler (`crown`) is released with the reason `Ärvde tronen`. Prisoners belong to the crown: when another family takes the throne every held record moves to the new ruling family (`passCrown`), except prisoners of that family itself, who are released with the reason `Hans ätt tog tronen`. An open ransom demand moves with its record: the story's `familyId`, `targetId` and description name the new captor. Validation refuses a `held` record whose person rules (`En fånge står som härskare.`) or holds an office (`En fånge innehar ett ämbete.`); a closed record is not checked, so an heir released as `Ärvde tronen` loads.

The ruler imprisons through the catalog entry `imprison` (cost 10 silver from the realm wallet, `actorOffice: ruler`), through `punish_crime`, or later through a plot story. An imprisonment that is not lawful (the person is not the subject of an exposed secret that `crimeOfSecret` records as a crime; an exposed opposition `plot` secret does not count, and `punish_crime` passes `lawful: true`) costs 5 legitimacy and 8 family grievance. `release_prisoner` and `execute_prisoner` (payload `{ prisonerId }`, one order each, a prisoner of the controlled family only) end a stay. `release_prisoner` and `execute_prisoner` are listed in the presentation's `actions` whenever the controlled family holds prisoners, with a `disabledReason` when the representative lacks the right; the `Intriger` tab shows that reason and disables `Frige` and `Avrätta`. The yearly `prisonerStep` runs near the end of `annualStep` (after `aiAnnual`, before `npcPlotStep`) on `plotRandom` only and does nothing once the campaign has ended. A prisoner held by his own family and a record with an open offer are skipped. For a prisoner the controlled family holds (a ruler is needed), a family that can pay offers a ransom (`ransom_offer` story with `accept` and `refuse`, open until the next annual date, when it lapses without any opinion change) with 60 % chance, otherwise it prepares a revolt (grievance, head opinion, a public event). For a prisoner another family holds, one draw per record and year: below 0.6 the captor demands the ransom when the prisoner belongs to the controlled family (`ransom_offer` with `familyId` the captor; `Betala lösen` pays from the family wallet without a mandate and is disabled with `Familjekassan räcker inte till lösen.` when the wallet is short, `Avstå` leaves him in prison), and otherwise his family pays when its treasury covers the ransom. A paid ransom goes to the realm treasury when the captor holds the crown, else to the captor's family treasury, and closes the record as `ransomed` with the public event `<name> löses ut`. `state.rngState` and `state.actionRngState` are never touched.

`state.rumors` holds `{ id: 'rumor-<n>', date, topic, subjectId, claimedActorId, truthful, reliability, sourceKind, sourceId, heardByFamilyId }` (`rumors.js`). `topic` is a key of `RUMOR_TOPICS` (`plot`, `murder`, `affair`, `illegitimate`), `reliability` is `osäker`, `trolig` or `säker`, `sourceKind` is `scheme` or `action`, and `heardByFamilyId` is a family id or `*` for every family. On each monthly check of an active scheme whose actor is outside the controlled family and that was not discovered on that check, `hearScheme` (called from `checkScheme`, so NPC schemes are heard too) lets the listener, the spymaster or else the active representative at half intrigue rounded down, hear it with chance clamp(5 + intrigue × 2, 5, 50) percent. The account is true with chance clamp(40 + intrigue × 3, 40, 95) percent, and reliability follows that accuracy (below 60 `osäker`, below 80 `trolig`, else `säker`). A false account names a living adult outside the actor's and the controlled family (never the target or a prisoner), picked by id order, or nobody when none qualifies. Murder is the topic of a `poison` scheme, plot of any other; a scheme yields at most three rumors. The effect `rumor` of `spread_rumor` plants a false rumor about the target, with no named culprit, heard by every family, and records its id in the log entry. Hearing, accuracy and the name pick draw only from `plotRandom`. `presentRumors` gives the last twenty heard by the family, newest first, and leaves out `truthful`, `sourceId`, `sourceKind` and `heardByFamilyId`; the prompt builder does not list rumors. When the target of a scheme belongs to the controlled family and its spymaster holds the office, the monthly discovery chance adds floor(spymaster intrigue / 2) before its clamp, and a bonus above 0 lifts that clamp from 40 to 55; the check still draws once from `actionRandom`.

## NPC plots

Once a year, in `annualStep` after `prisonerStep` (`npcPlotStep`, npcPlots.js), people outside the controlled family plot, on `plotRandom` only. (1) Against the throne: candidates are living adults who can act, not in prison, not of an exiled family, whose family treasury covers an undermine (15). Score = −opinion(candidate → target) + 15 if ambitious + 15 if vengeful + intrigue − fear × (0.4 if cautious or craven, else 0.15); the target is the ruler in realm mode and the representative in family mode. The best candidate (ties by id) plots when the score is at least 20 and `plotRandom() × 100 < clamp(score / 2, 0, 40) × aggression` (easy 0.5, normal 1, hard 1.5); the action is `poison` from a score of 60, else `undermine`, and a plotter whose family cannot pay for that action starts nothing and costs no draw. At most one NPC scheme against the controlled family is active. (2) Feud: the pair of adults from two different non-controlled families with the lowest mutual opinion (the average of the two) below −10 starts an `undermine` when `plotRandom() < 0.2`; the one who thinks worse of the other plots; at most two feuds are active. (3) Affairs: a married, living adult outside the controlled family whose opinion of a living spouse is 0 or lower, and who is not the subject of an unexposed `affair` secret, gets a weak `affair` secret (subject and holder the person) when `plotRandom() < 0.08`. Draw order: plot against the throne, feud, then affairs in id order; nothing is drawn before every other check has passed.

A scheme is started through `resolveAttempt` with the NPC context (no order, paid by the plotter's family, `means` empty, command id `npc-plot:<date>:<n>`, `playerControlled: false`). It stores `secretId`, a weak `plot` secret about the plotter that only he holds; this is not `means.secretId`, which is blackmail leverage, and `validateSchemes` requires it to name a secret whose subject is the actor. When such a scheme is discovered and its target belongs to the controlled family, the secret gains the target and the representative as holders with strong evidence and the story `plot_uncovered` opens (public, due after 12 months, closed earlier if the plotter dies or is imprisoned, becomes ruler or the active or household representative, or joins the controlled family). A scheme an NPC started through `npc_intent` has no `secretId`; `uncoverPlot` first gives it a weak `plot` secret about the actor, held by him, and then goes on as above. Its choices: `imprison` (lawful, disabled unless the representative is the ruler), `expose` (`treason` when the target was the ruler at discovery (`targetWasRuler`), `attempted_murder` for a poisoning, else the plot secret goes public), `hook` (the representative gains a strong hook over the plotter; disabled with `Du har redan ett grepp över personen.` when the representative already holds an active hook over him) and `ignore`. The model's `npc_intent` list leaves out entries that need an office or the realm treasury (`imprison`).

## Phase 2 state, streams and commands

`state.extensionsVersion` is 2. `ensureCharacterExtensions` migrates a version 1 state additively and idempotently on every load and command, draws no randomness, and refuses any other version through validation. Version 2 adds `plotRngState`, the ledgers `occasions`, `prisoners`, `rumors` and `conversations` next to the version 1 ones (`secrets`, `hooks`, `relationships`, `schemes`, `actionLog`), and the office `spymaster` (`Spionmästare`, kind `council`, vacant). The ruler fills it with `appoint`; the yearly auto-fill of vacant offices skips it, because filling it would shift the main stream.

Three random streams, none shared:

- `state.rngState`: the main stream of the annual simulation. Phase 2 leaves the order of its draws in `annualStep` as it was in Phase 1.
- `state.actionRngState`: action and scheme rolls, refusals, the monthly discovery check and the one roll of a conversation request.
- `state.plotRngState`: an xorshift state that is never 0, seeded once by ensure as the FNV-1a hash of `` `${polityId}|${startedAt}|${rngState}|plots` `` (`>>> 0 || 1`). `plotRandom(state)` in `extensions.js` draws from it for NPC plot choice (`npcPlotStep`), rumor hearing, rumor accuracy and the false-name pick (`rumors.js`), and ransom offers and demands (`prisonerStep`). Nothing else uses it.

Estimates, presentations, prompt building, migration and validation draw no randomness and spend nothing.

A secret is `{ id, type, subjectId, holderIds, evidence, causeId, exposed, createdAt }` with `type` one of `murder`, `affair`, `illegitimate_child`, `heresy`, `plot` (`SECRET_LABELS` gives the Swedish names) and `evidence` `weak` or `strong`. A hook is `{ id, ownerId, targetId, strength, causeId, createdAt, usedAt }`: a weak hook gets `usedAt` on its first use, a strong one stays usable. The representative's presentation lists `knownSecrets` (type label, subject name, evidence label, `exposed`) and `ownHooks`; who else holds a secret never leaves the engine. `crimes.js` turns an exposed crime secret into a public event, opinion loss in the victim's family, legitimacy loss when the criminal is the ruler and, for another criminal under a ruling player, a `punish_crime` decision titled `<crime label>: <name>`. The decision closes when the criminal dies, sits in prison, becomes ruler or the active or household representative, or when it falls due.

Occasions (`occasions.js`): `hold_feast` (payload `{}`) charges 30 family silver and one order, refuses a second feast within twelve months with `Familjen höll gästabud för mindre än ett år sedan.`, and pushes `{ id: 'occasion-<n>', kind: 'feast', hostFamilyId, hostId, startedAt, endsAt, guestIds }` that runs for one month. `hostId` is the household representative who paid, who may be a guardian from another family, so validation only checks that the host exists. The guests are every living adult who is not in prison; each guest family's head thinks 5 better of the host for three years. While a feast runs, an intrigue-category action against a guest gains the odds rows `Gästabudet ger tillträde` (+15 success) and `Hemlighållning: många vittnen på gästabudet` (−5 secrecy) when the acting family hosts it: the player's context reads the controlled family's feast, so a guardian from another family uses it too, and an NPC context reads the actor's own family. A scheme stores the feast it started under in `means.occasionId`; only a scheme's due-date estimate (`means.scheduled`) honours it, and a `means.occasionId` sent by a player is ignored. `presentOccasions` lists the feasts the controlled family hosts today.

Conversations (`conversation.js`): `converse_request` (payload `{ personId, kind, offerSilver, hookId, arguments, argumentScore }`, `kind` one of `support`, `reveal_secret`, `pledge`) is an engine-only command. `handleCommand` accepts it only with `command.origin === 'converse'`, which `submitConversationRequest` in `characterRuntime.js` is the only caller to set, and refuses any other origin with `Samtalsförfrågningar kan bara göras i samtalssteget.`. `estimateConversation` is pure: the base chance per kind plus labelled rows (opinion, loyalty, offer, traits, hook, `Övertygande argument`), cut to 5 to 95, shown at the representative's diplomacy precision. An argument (`offer`, `shared_enemy`, `shared_memory`, `hook`) counts only when it refers to something real in the state, and the model's claimed `argumentScore` is capped at 10 again. An `offer` argument counts from 20 silver, where the gift row reaches 5, half of that cap; a smaller gift keeps its row but grounds nothing. A hook that an active scheme holds in `means.hookId` cannot be offered (`Övertaget är bundet till en pågående plan.`). Resolution draws one `actionRandom`, pays the offer from the family wallet without an order, spends a weak hook, writes a memory and a `conversations` entry `{ id: 'conversation-<n>', personId, kind, date, value, roll, accepted, effects }`, and applies the effect: support +10 opinion, a secret shared, or a hook granted. A person is asked once per twelve months. `getConversationBrief` is engine-side input for the model and is never part of the presentation. It carries only memories that involve the speaker or the representative and that both know, the secrets both hold (type label and subject name), and the representative's hooks over the speaker that no active scheme holds; a private memory or a secret only the speaker holds never reaches the model.

Presentation fields added in Phase 2: `occasions`, `prisoners`, `rumors`, `knownSecrets`, `ownHooks` and `conversationTargets`.

## Phase 3 state, streams and commands

`EXTENSIONS_VERSION` is 3. Saves migrate additively. `state.reign` holds the ruler, the start date, goals, deeds, prestige sources and `lostOrders`. `state.nicknames`, `state.familyDemands` and `state.factions` are lists.

Commands: `set_reign_goal` and `reward_councillor`. Story types: `stress_breakdown`, `family_demand` and `faction_ultimatum`, all dispatched through `COURT_STORY_TYPES` in `court.js`.

Streams: `demandStep` and `factionStep` draw from `plotRngState`, after `npcPlotStep`. `crush` draws once from `actionRngState`, inside `resolveUltimatum`. Reads, odds and the expiry of a story draw nothing.

Presentation: `court` is new, and `people[].loyalty` is gone. `people[].loyaltyReading` gives a label at the reader's precision. `presentFactions` is the only reader that names faction members, and it names only `knownMemberIds`. A crush or a deposition puts every member into `knownMemberIds`. A dissolved or voided faction reveals nobody. The year prompt receives `view.court` and nothing else from these systems.

Annual accounting: the existing year event reports actual base administration receipts plus the chancellor's paid treasury delta, including clamps and rounding. Loyalty drift precedes the chancellor payment; `courtAnnualStep` still runs after `npcPlotStep`. The aggregate uses cents internally and retains its one-decimal Swedish sentence. The engine completes that event after court processing, preserving its ID, log position and public shape. It persists no separate contribution or numerical service/loyalty field. Other story and plot transactions retain their own event handling; `economy.annualRevenue` remains the base estimate.

Legacy replay: for a raw pre-Phase-3 character state without a reign, the host adapter reconstructs stored patches before migrating each resulting checkpoint. Event normalization validates a legacy full checkpoint while retaining its raw payload for subsequent patches. `createLegacyCharacterReplay` follows the adapter's per-event boundary after date synchronization and host reconciliation, so an intervening model event's calendar progress reaches the legacy base. Applying a checkpoint returns a validated current state. A current-version checkpoint or an authorized stored command ends legacy compatibility handling. Replay uses saved outcomes, draws no extra randomness and calls no model; it persists no provenance marker. Source, gate and revision checks remain strict, and current-version reign/office mismatches remain invalid. `rulesVersion`, `contentVersion` and `EXTENSIONS_VERSION` remain unchanged.

## Model proposals and the gate

A model never changes character state directly. Its `impacts.characterOps` reach the state only through `prepareCharacterTimeline`:

1. `realm_effect` and `npc_intent` are engine-only. `handleCommand` accepts them only with `command.origin === 'gate'`, which only `prepareCharacterTimeline` sets; a player command of these types is refused with a Swedish sentence (`submitCharacterCommand` always sends `origin: 'player'`). Per model turn (one `prepareCharacterTimeline` call) at most 4 `realm_effect` and 3 `npc_intent` run; each later one is refused with a notice that the limit per tur is reached, and a proposal id seen earlier in the turn is refused too. Each runs with id `<event id>:gate:<date>:r<revision>:<index>`, `origin: 'gate'` and the current revision, so the id is unique across turns; a duplicate result is listed as a refusal. An accepted result with a public event becomes a `character-system` event through `characterTransitionEvents`, so replay applies its patch and never rolls again. A quiet result (an NPC tier the player may not see, a silent scheme start) adds no card: its changes fold into the patch of the model event's next or last gate card, and when the model event has no gate card they ride on the model event itself as one patch marked `gate: true`. Replay applies an event's `characterOps` after its other impacts, the point where the gate ran. Refusals add one Swedish notice event, "Modellens förslag avvisades", per model event, listing each refusal. An `npc_intent` refusal reads only "Ett förslag om en annan familjs handling avvisades." and names no actor, action or amount; a `realm_effect` refusal keeps its reason.
2. `realm_effect { treasury, legitimacy, armyStrength, reason }`: integer changes, each optional and at least one non-zero, within treasury −80…+40, legitimacy −10…+5, armyStrength −15…+10. A value outside its range refuses the whole command. `reason` is a non-empty Swedish string of at most 200 characters. The fields clamp to their existing bounds: treasury at 0, legitimacy and `realm.armyStrength` (the base of military readiness) at 0 and 100. A dissolved realm refuses it.
3. `npc_intent { actorId, actionId, targetIds }` runs the `attempt_action` rules for an NPC: a living adult who is neither the household nor the active representative and not a member of the controlled family. Targets are free, so NPCs may act against the player's people. The NPC context has `playerControlled: false`, orders only its actor, draws no refusal, and applies the difficulty modifier against the active representative. The cost comes from `state.families[actor.familyId].treasury` with no action points and no player stress; a family that cannot pay refuses the intent before any draw. A scheme intent starts a scheme like the player's, stored with `playerControlled: false`; at the due date it is estimated with the same NPC context and hires agents from the actor's family. A quiet NPC tier stays out of the public log.
4. Every other command type in a model event is advisory: it is not executed, and the timeline shows "Förslaget kräver ditt beslut".
5. `applyCharacterOpsToWorld` executes stored commands only for `character-system` and `game-master` events. A stored `ai` event never executes a command, also on replay. Patches apply only from `character-system` events, and from another event only when marked `gate: true`; `prepareCharacterTimeline` empties the model's own `characterOps` before it writes that patch, and the model's schema allows only commands.
6. `projectCharacterWorld` is the only writer of the character polity's leader, stability, treasury and military readiness in the host world.
7. A non-engine event may dissolve the character polity only when the same event settles its mapped territory: the polity held at least one region before the event and holds none after it. A bare dissolve is refused with the warning `[character realm] refusing to dissolve the character polity "<code>" from a non-engine event.`

`buildCharacterPromptContext` states this contract to the model, with each contested catalog entry's id, label and target rule.

## Historical initialization

The canonical pure engine lives under `server/characters/`; `src/runtime/characters/` retains compatibility exports. The calendar, start policy and historical schema follow the same arrangement so installed desktop packages can import the engine without a source tree.

`createHistoricalCharacterSystem({ historicalScenario, date, polityId, mode, familyId, seed, difficulty })` converts a validated authored court into the current state format. The factory performs court/reference checks and throws a Swedish refusal on unsupported content. Callers validate the full scenario, geometry and manifest with `validateHistoricalScenario` first. The factory performs no I/O and activates no game. The existing no-options Hadara fixture and its saved random streams remain unchanged.

Historical states retain the existing engine schema/rules/content versions. `historicalOrigin` holds public content identity, bookmark, chronology, context, coverage and source provenance. Each authored person has `identityOrigin`, `originLabelSv` and a separate `historicalOrigin.claims` record. A religion keeps its public `identity` and `mechanics` claims in `historicalOrigin.claims`; saves from before this field carry none. A missing birth date receives a generated simulation date with an explicit provenance label. Unknown culture stays `Ej belagd`; the factory infers no biological parents. Numerical attributes, resources, succession mechanics and governor offices are generated game rules. Children born during play have generated identity and genealogy labels. Shared portrait fallback artwork does not represent a researched historical likeness.

Presentation copies only the defined provenance fields. Private secrets, faction records and loyalty remain in their existing engine stores. JSON normalization preserves people and provenance without reseeding. The opt-in runtime initializer validates historical world content and map assets before writing; it returns existing character state unchanged and refuses invalid historical content without a Hadara fallback. Task 5 integrates new-start defaults, guards and UI activation on both adapters; Task 6 and final documentation review are accepted with the limits recorded in the play script; current-head CI is required before merge.

An authored court may set `successionLaw` to `primogeniture`, `merit` or `elective`; an absent law means `primogeniture`, and the seed writes the law before it records the opening heir claim. A package polity may set `kind` to one of `POLITY_KINDS` (`state`, `city-state`, `confederation`, `chiefdom`, `non-state`); an absent kind means `state`. The factory copies the chosen polity's kind to `state.realm.kind` and refuses a `non-state` polity with the Swedish court refusal. A fictional start gets `state`, and `ensureRealmKind` fills `state` in saves without the field and draws nothing. Only the `non-state` refusal depends on the kind today. Presentation `realm` carries `kind`, `kindLabelSv`, `successionLaw` and `successionLawLabelSv`, and the `Ämbeten & arv` view shows `Tronföljd: <label>`.

Authored historical person IDs must avoid `person-<number>`, which the runtime reserves for generated people. The factory refuses that namespace before initialization writes; existing saves and the runtime allocator retain their behavior. Content authors must choose stable IDs outside the reserved namespace. Optional `historicalOrigin.coverage`, when present in a save, must be an array of records with nonempty `area`, `status` and `noteSv` strings and a `sourceIds` array of nonempty strings. Normalization refuses malformed entries with a Swedish validation error before presentation; omitted coverage remains supported.

## Historical record in the chronicle

The chronicle tab of the character panel has a third segment, `I verklighetens historia`, for campaigns whose `world.historicalScenario` is set. It lists the catalog events of every calendar year the campaign has closed, newest year first, each under a year heading in the panel's own era form (`218 f.Kr.`, `802 e.Kr.`). A lower `gameDate` after an undo drops the later years. The view loads the approved catalog through `loadHistoricalEventCatalog` when the segment is first shown, and this view does not read the catalog before the segment is shown. A rejected load shows the empty text. Once the game has passed AD 1200 the view adds a note that the research ends at year 1200.

The view is derived from `startDate`, `gameDate` and the catalog. It makes no model call, changes no runtime slice, writes nothing to the save and does not touch `state.rngState`. The popup's link `Visa alla i krönikan` dispatches the window event `oh:open-history-record`. `GameUI/main.jsx` listens for it, opens the panel and passes a counter prop, `chronicleRequest`. The panel reacts to a changed counter by selecting the chronicle tab and this segment, and moves focus into the panel when it is outside. The catalog ships empty until the research round, so no popup appears and the segment shows its empty text.
